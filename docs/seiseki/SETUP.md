# 麻雀成績管理（段階1）設定手順

この手順は Firebase コンソールと Vercel の画面で行います。コードからは本番の設定を変更しません。
ルールの全文は `docs/seiseki/firestore.rules` にあります。

順番どおりに進めてください（1→2→3→4）。

---

## 1. スタッフ用アカウントを作る（Firebase Authentication）

1. Firebase コンソールでプロジェクト **siten-fee7d** を開く
2. 左メニュー「構築」→「Authentication」→（初回のみ）「始める」
3. 「Sign-in method」タブ →「メール / パスワード」を選び、**有効にする**をオンにして保存
   - 「メールリンク（パスワードなしでログイン）」はオフのままで構いません
4. 「Users」タブ →「ユーザーを追加」
   - メールアドレス: 共用アカウント用のアドレス（実在するアドレスを推奨。パスワード再設定に使えます）
   - パスワード: 推測されにくいもの（12文字以上を推奨）
5. 追加されたユーザーの **ユーザー UID** をコピーしておく
6. （推奨）「Settings」タブ →「ユーザー アクション」で **「作成（登録）を有効にする」のチェックを外す**
   - 外部の人が勝手にアカウントを作れなくなります。外さなくても、手順2の登録がないアカウントは書き込めません
   - 画面の表記は多少異なることがあります

## 2. スタッフとして登録する（Firestore）

1. 左メニュー「Firestore Database」→「データ」タブ
2. 「コレクションを開始」→ コレクション ID に `seisekiStaff`
3. ドキュメント ID に **手順1-5でコピーした UID** を貼り付け
4. フィールドを1つ追加: フィールド名 `name`、型 string、値 `共用`
5. 保存

※ あとでスタッフを増やすときは、Authentication でユーザーを追加し、同じように `seisekiStaff` にその UID の文書を足すだけです（ルールの変更は不要）。
※ 権限を外すときは、`seisekiStaff` からその UID の文書を削除します。

## 3. Firestore ルールを設定する

貼り付けるのは `docs/seiseki/firestore.rules` の**全文**です（今のルールと置き換えます）。

### 前提（2026-10 に確認した今の状態）

- 今のルールは、全体を許可する1つだけ:
  `match /{document=**} { allow read, write: if request.time < timestamp.date(2036, 12, 31); }`
- 今あるコレクションは9つ: boardMeta, eventApplications, events, lineUsers, phoneToLineUserId, reservations, settings, siteChats, tables
  （lineUsers の下に messages などのサブコレクションあり）

### 新しいルールでの変化

| 場所 | 今 | 新しいルール |
|---|---|---|
| 既存の9コレクション（サブコレクションも含む） | 誰でも読み書き可（2036年末まで） | 誰でも読み書き可（**期限なし**）。動きは変わらない |
| 成績（players・games・dailyFlags） | 誰でも読み書き可 | 読み取りは公開、書き込みはスタッフのみ（履歴つき） |
| 成績（seisekiHistory） | 誰でも読み書き可 | 読み取りはスタッフのみ、追加だけ可（書き換え・削除不可） |
| 成績（seisekiStaff） | 誰でも読み書き可 | 本人が自分の分を読めるだけ。追加・削除はコンソールから |
| 上のどれでもないコレクション | 誰でも読み書き可 | **読み書きできない** |

- 全体を許可する `match /{document=**}` は**入れません**。1つでも全体を許可する行があると、成績の制限が効かなくなります（Firestore のルールは、どれか1つでも許可していれば通るため）
- 今後、新しいコレクションを使う機能を追加するときは、ルールの「既存のコレクション」の部分に1行追加が必要です（追加しないと、その機能は読み書きできません）

### 3-1. 今のルールを控える（必ず最初に）

1. 「Firestore Database」→「ルール」タブ
2. 表示されているルールを **全部選択してコピーし、メモ帳などに貼って保存**（ファイル名例: `firestore-rules-backup-2026-10-13.txt`）

### 3-2. ルールを貼る

1. エディタの中身を**全部消して**、`docs/seiseki/firestore.rules` の全文を貼り付ける
2. 「公開」を押す（反映まで1分ほどかかることがあります）
   - 公開ボタンを押したときにエラーが出た場合は、公開せずにそのメッセージを送ってください

### 3-3. 動作確認

- お客様側の予約画面で予約一覧が表示され、予約ができる
- `/board` が表示され、店舗管理の「卓状況」で対局開始・本日の予定の追加ができる
- 店舗管理の「予約一覧」「チャット」「サイトチャット」「教室・大会」「設定」が表示される
- LINE のメッセージ受信（チャットに新しいメッセージが届く）
- `/seiseki/admin` でログインし、名簿登録・対局登録・編集・削除・元に戻す・日別成績のチェックができる

### 3-4. うまく動かなかったときに元に戻す

- 「ルール」タブで、3-1 で保存したテキストを **全部貼り直して「公開」**
- または、ルール編集画面の左側にある **変更履歴** から以前のバージョンを選んで戻す
- 元に戻すと、すべてのコレクションが今まで通り誰でも読み書きできる状態に戻ります（成績も誰でも書ける状態になります）
- どの画面が動かなかったかを教えてください。ルールに足りない場所を追加します

## 4. 毎日の自動バックアップを設定する（Vercel Blob・Private）

毎日 日本時間 4時台に、成績データ（名簿・対局・日別チェック・変更履歴）を1つの JSON ファイルにまとめて
Vercel Blob に保存します。90日を過ぎたファイルは自動で消します。

バックアップには変更履歴（スタッフのメールアドレスを含む）が入るため、**Private のストアにだけ保存します**。
Private のファイルは URL を知っていても読めず、Vercel のダッシュボードか、トークンを持つプログラムからしか取り出せません。
コードは常に Private を指定して保存し、Public を指定する設定は持たせていません。ストアを Public で作ってしまった場合は保存がエラーになる見込みです（下の 8 で必ず確認してください）。

1. Vercel のダッシュボードで、このサイトのプロジェクトを開く
2. 「Storage」→「Create Database」（または「Create」）→ **Blob** を選ぶ
3. 作成画面でアクセス方式（Access）に **Private** を選んで作成する
   - ストアのアクセス方式は、あとから変えられない可能性があります。迷ったら作り直してください
4. 作成後、このプロジェクトに接続（Connect）する。環境変数 `BLOB_READ_WRITE_TOKEN` が自動で追加されます
5. 「Settings」→「Environment Variables」に追加（Production）
   - `SEISEKI_BACKUP_EMAIL` … 手順1で作ったアカウントのメールアドレス
   - `SEISEKI_BACKUP_PASSWORD` … 同パスワード
   - （任意）保存日数を変える場合: `SEISEKI_BACKUP_KEEP_DAYS` = 日数（既定 90）
   - `FIREBASE_API_KEY` と `CRON_SECRET` は既存のものをそのまま使います
6. 再デプロイ（Deployments → 最新 → Redeploy）
7. 「Settings」→「Cron Jobs」で `/api/seisekiBackup` が表示されていることを確認し、「Run」で1回手動実行
8. 「Storage」→ 作った Blob →「Browser」に `seiseki-backups/seiseki-日付-xxxx.json` ができていれば完了
   - ファイルができていない場合は「Logs」で `成績バックアップエラー` を探し、内容を送ってください

※ パスワードを変更したときは、`SEISEKI_BACKUP_PASSWORD` も変更して再デプロイしてください。
※ Vercel のプランによって Cron の数や Blob の無料枠に上限があります。デプロイ時に Cron の数のエラーが出た場合は連絡してください。

### 作成画面で Private を選べない場合

Private のストアは Vercel Blob では比較的新しい機能のため、アカウントやプランによってはまだ選べないことがあります（使っているライブラリは Private に対応済みです）。
その場合は Public で作らず、次のどれかにします。決めていただければ対応します。

- **A. Firebase の公式バックアップ（おすすめ）**
  Firestore の「スケジュールバックアップ」を毎日にします。データは Google Cloud の中にだけ置かれ、公開されません。
  Firebase を従量課金（Blaze）プランにする必要があります（このデータ量なら費用はごく小さい見込みですが、料金はコンソールで確認してください）。
  この場合、Vercel 側のバックアップ（`/api/seisekiBackup`）は使わないので、`vercel.json` の Cron 1行を外します。
- **B. 暗号化してから保存する**
  バックアップをパスワード（環境変数に置く鍵）で暗号化してから Public ストアに保存します。URL が漏れても中身は読めません。
  鍵をなくすと復元できなくなるので、鍵の保管が必要です。
- **C. 履歴をバックアップに入れない**
  バックアップは名簿・対局・日別チェック（もともと公開しているデータ）だけにし、履歴は Firestore の中だけに残します
  （履歴はルールで書き換え・削除ができないため、Firestore 内では守られています）。手軽ですが、Firestore 全体を失った場合は履歴も失います。

## 復元について

- 削除した対局: `/seiseki/admin` の記録一覧の下「削除済み（n件）を表示」→「元に戻す」
- 間違って編集した対局: 「履歴」で変更前の値を確認し、「編集」で入れ直す（その操作も履歴に残ります）
- データ全体の復元が必要になった場合: バックアップの JSON から戻す作業になります（専用の復元ツールはまだ作っていません）
