# 麻雀成績管理（段階1）設定手順

この手順は Firebase コンソールと Vercel の画面で行います。コードからは本番の設定を変更しません。
ルールの全文は `docs/seiseki/firestore.rules` にあります。

順番どおりに進めてください（1→2→3→4）。

---

## 1. スタッフ用アカウントを作る（Firebase Authentication）

1. Firebase コンソールでプロジェクト **siten-fee7d** を開く
2. 左メニュー「構築」→「Authentication」→（初回のみ）「始める」
3. 「Sign-in method」タブ →「メール / パスワード」を選び、**有効にする**をオンにして保存
   - 「メールリンク（パスワードなしでログイン）」はオフのままで構いません
4. 「Users」タブ →「ユーザーを追加」
   - メールアドレス: 共用アカウント用のアドレス（実在するアドレスを推奨。パスワード再設定に使えます）
   - パスワード: 推測されにくいもの（12文字以上を推奨）
5. 追加されたユーザーの **ユーザー UID** をコピーしておく
6. （推奨）「Settings」タブ →「ユーザー アクション」で **「作成（登録）を有効にする」のチェックを外す**
   - 外部の人が勝手にアカウントを作れなくなります。外さなくても、手順2の登録がないアカウントは書き込めません
   - 画面の表記は多少異なることがあります

## 2. スタッフとして登録する（Firestore）

1. 左メニュー「Firestore Database」→「データ」タブ
2. 「コレクションを開始」→ コレクション ID に `seisekiStaff`
3. ドキュメント ID に **手順1-5でコピーした UID** を貼り付け
4. フィールドを1つ追加: フィールド名 `name`、型 string、値 `共用`
5. 保存

※ あとでスタッフを増やすときは、Authentication でユーザーを追加し、同じように `seisekiStaff` にその UID の文書を足すだけです（ルールの変更は不要）。
※ 権限を外すときは、`seisekiStaff` からその UID の文書を削除します。

## 3. Firestore ルールを設定する

### 3-1. 今のルールを控える（必ず最初に）

1. 「Firestore Database」→「ルール」タブ
2. 表示されているルールを **全部選択してコピーし、メモ帳などに貼って保存**（ファイル名例: `firestore-rules-backup-2026-10-05.txt`）
3. 今のルールに、次のような「全部まとめて許可」の行があるか確認する
   ```
   match /{document=**} {
     allow read, write: if true;     ← または  if request.time < timestamp.date(...)
   }
   ```

### 3-2. ルールを貼る

**A. 「全部まとめて許可」の行が無い場合**
- 今のルールはそのまま残し、`docs/seiseki/firestore.rules` の
  「▼▼▼ ここから 麻雀成績 ▼▼▼」〜「▲▲▲ ここまで 麻雀成績 ▲▲▲」の部分だけを、
  今のルールの `match /databases/{database}/documents {` の中（最後の `}` `}` の手前）に貼り付ける

**B. 「全部まとめて許可」の行がある場合**
- その行があると、成績の制限が効きません（Firestore のルールは、どれか1つでも許可していれば通るため）
- `docs/seiseki/firestore.rules` の全文で置き換えてください。既存のコレクション（予約・チャット・卓状況など）は、
  コレクションごとに「今まで通り誰でも読み書きできる」と書き直してあるので、動きは変わりません
- 今の行が `if request.time < timestamp.date(...)`（期限つきのテストモード）だった場合は、期限が来ると既存機能も止まる設定です。置き換えると期限はなくなります

どちらか分からない場合は、控えたルールを送ってください。確認します。

3. 「公開」を押す（反映まで1分ほどかかることがあります）

### 3-3. 動作確認

- お客様側の予約画面・`/board`・店舗管理（予約一覧・チャット）がいつも通り動く
- `/seiseki/admin` でログインし、名簿登録・対局登録・編集・削除・元に戻す・日別成績のチェックができる

### 3-4. うまく動かなかったときに元に戻す

- 「ルール」タブで、3-1 で保存したテキストを **全部貼り直して「公開」**
- または、ルール編集画面の左側にある **変更履歴** から以前のバージョンを選んで戻す
- 元に戻すと、成績の書き込みは A の場合は拒否され、B の場合は誰でも書ける状態に戻ります（予約などの既存機能は元どおり動きます）

## 4. 毎日の自動バックアップを設定する（Vercel）

毎日 日本時間 4時台に、成績データ（名簿・対局・日別チェック・変更履歴）を1つの JSON ファイルにまとめて
Vercel Blob に保存します。90日を過ぎたファイルは自動で消します。

1. Vercel のダッシュボードで、このサイトのプロジェクトを開く
2. 「Storage」→「Create Database」（または「Create」）→ **Blob** を選んで作成
   - アクセス方式を選べる場合は **Private** を選ぶ
   - 作成後、このプロジェクトに接続（Connect）する。環境変数 `BLOB_READ_WRITE_TOKEN` が自動で追加されます
3. 「Settings」→「Environment Variables」に追加（Production）
   - `SEISEKI_BACKUP_EMAIL` … 手順1で作ったアカウントのメールアドレス
   - `SEISEKI_BACKUP_PASSWORD` … 同パスワード
   - Blob ストアを Public で作った場合のみ: `SEISEKI_BACKUP_ACCESS` = `public`
   - （任意）保存日数を変える場合: `SEISEKI_BACKUP_KEEP_DAYS` = 日数（既定 90）
   - `FIREBASE_API_KEY` と `CRON_SECRET` は既存のものをそのまま使います
4. 再デプロイ（Deployments → 最新 → Redeploy）
5. 「Settings」→「Cron Jobs」で `/api/seisekiBackup` が表示されていることを確認し、「Run」で1回手動実行
6. 「Storage」→ 作った Blob →「Browser」に `seiseki-backups/seiseki-日付-xxxx.json` ができていれば完了

※ パスワードを変更したときは、`SEISEKI_BACKUP_PASSWORD` も変更して再デプロイしてください。
※ Vercel のプランによって Cron の数や Blob の無料枠に上限があります。デプロイ時に Cron の数のエラーが出た場合は連絡してください。

## 復元について

- 削除した対局: `/seiseki/admin` の記録一覧の下「削除済み（n件）を表示」→「元に戻す」
- 間違って編集した対局: 「履歴」で変更前の値を確認し、「編集」で入れ直す（その操作も履歴に残ります）
- データ全体の復元が必要になった場合: バックアップの JSON から戻す作業になります（専用の復元ツールはまだ作っていません）
